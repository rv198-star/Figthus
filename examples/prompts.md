# Prompt Examples

下面这些 prompt 可以直接复制到 Codex 里使用。

## 只做配图规划

```text
Use $figthus 先不要生图。
请分析下面这篇文章哪里值得配图，输出 5 张左右的 shot list。
不要平均配图，只挑认知锚点。
每张图写清楚：
- 放在哪个段落后
- 图的主题
- 认知锚点
- 核心意思
- 可视动作
- 出场角色
- 未出场角色留下什么痕迹
- 角色状态
- 建议元素
- 建议中文标注词

<粘贴文章>
```

## 文章正文配图

```text
Use $figthus 把下面这篇文章生成 4 张 Figthus 正文配图。
先判断每张图使用 restrained-object-vignette、trace-object 还是 character-led；不要默认让破橡皮拟人化。角色正文图才使用 16:9、纯白和少量中文批注，物件小品优先保持小主体和大留白。
每张图只讲一个认知动作，不要做 PPT 信息图，不要儿童文具海报。
烂笔头和破橡皮不必每张图同时出现；按认知动作选择出场角色，未出场的一方用铅笔线、擦痕、灰屑、空白、断芯或证据单体现。

<粘贴文章>
```

## 长文配图策略

```text
Use $figthus 给这篇长文做配图策略。
只挑适合画的认知动作：第一版被推出去、证据被拖回来、假清楚被擦掉、失败被分类、停止规则、从空白重启。
默认 6-8 张，先输出 shot list，不要生成图片。

<粘贴文章>
```

## 按核心动作生成一组样张

```text
Use $figthus 为这篇文章生成 6 张正文配图。
优先从这些动作里选：第一笔推出去、证据拖回来、假清楚被擦掉、停止闸、从空白重启、裂开了。
每张图只讲一个动作，中文标注最多 3 个，不要左上角标题，不要 PPT 信息图。

<粘贴文章>
```

## 对齐 Figthus 成品密度

```text
Use $figthus 参考仓库里的 examples/images 样张密度，为这个观点生成 1 张图：

结果要带着证据回来，而不是让 AI 原地多试几次。

要求：白底、手绘、留白多；可以双角色同屏，也可以只让破橡皮拖回证据，但要让第一版的铅笔痕迹仍然在画面里。
```

## 单个观点生成一张图

```text
Use $figthus 为这个观点生成一张 16:9 正文配图：

先写错，才有东西可以擦近一点。

画面要怪诞但清爽。可以只出现烂笔头制造第一条痕迹，也可以双角色同屏；如果破橡皮不出场，画面里要留有擦痕、灰屑或空白预示下一步修正。
中文标注最多 5 个，短一点。
```

## 工作流主题

```text
Use $figthus 为“Loop Engineering 不是多试几次，而是让结果带着证据回来”生成一张正文配图。
不要画正式流程图，不要把 Loop Engineering 写成标题。
请重新发明一个低科技隐喻，让烂笔头推出第一版，让破橡皮拿证据判断改哪里。
```

## 改图：去掉标题

```text
Use $figthus 帮我编辑这张图。
去掉左上角的“Workflow / 流程图”标题和下划线，其他内容保持不变。
不要新增任何文字或物件。
```

## 改图：明确出场逻辑

```text
Use $figthus 这张图方向对，但出场角色和痕迹关系不明显。
请保持核心意思不变，重生成一版：烂笔头负责制造第一版痕迹，破橡皮负责依据证据擦掉假清楚。
画面更怪一点，但仍然纯白、清爽、少字。
```

## 改图：裂开了状态

```text
Use $figthus 让这张图里的破橡皮进入“裂开了”状态。
保持构图和核心意思不变。破橡皮沿粉色和灰白断面自然裂开，不要画绳子，不要画完整橡皮块。
```

## 六宫格叙事连环画

```text
Use $figthus 把下面的文章浓缩成一张 3×2 的 narrative-comic-6 连环画，而不是生成多张正文插图。

先判断这张图覆盖 whole-article，还是一个 local-complete 的局部完整观点。写 Coverage contract：来源边界、核心观点、论证链和明确排除的内容。再写 Narrative promise，并输出六格 beat sheet；每格写 argument job、变化、具体场景、图内短句、跨格持续线索和角色状态。六格共同覆盖“起题 → 旧解/压力 → 转折 → 展开 → 限定/深化 → 收束”；如果整篇无法诚实压成一个完整观点，不要偷偷截取局部并声称覆盖整篇，也不要发明原文没有的边界或反例。

生成时保留 Figthus 的残损文具 IP 和克制手绘感；一张 1:1 成图、3 列 × 2 行、清楚白色格线、从左到右再从上到下阅读。不要复制任何参考六宫格中的角色、黄底、字句或构图。中文只保留每格一句短文案；同时保存 comic-script.md，以便发布前后期叠字和校对。

<粘贴文章>
```

## 自动选择交付模式

```text
Use $figthus 为下面这篇公众号文章设计并生成最有价值的视觉交付。

不要预设多张正文配图或六宫格。请先判断是否同时满足：观点完整、六格确有推进、脱离正文仍有传播价值、存在跨格视觉连续性、短文案可以保住论证。输出简短 Delivery decision，并说明为什么没有选择另一种模式。若选择 narrative-comic-6，继续完成 Coverage contract、分镜和合成图；否则完成正文配图策略并逐张生成。不要停下来等我确认。

<粘贴文章>
```
