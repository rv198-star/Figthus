# QA Checklist

## 必过项

### 交付模式路由

- 用户明确指定交付形式时遵守其选择，没有擅自改成另一种模式。
- 用户未指定形式时，先记录 `Delivery decision`，不能默认多张正文配图，也不能默认六宫格。
- 自动选择六宫格时，观点完整、确有推进、独立传播增益、可视连续性、可压缩性五项全部通过。
- 任一门槛不通过时选择正文配图；只有一个认知动作时选择单张插图或物件小品。
- `Alternative rejected` 说明另一种交付为什么价值更低，而不是只复述最终选择。

### 六宫格叙事连环画（仅 narrative-comic-6）

- 成图是一张完整的 3×2 六格合成图，有清晰外边距、格线和左到右、上到下的读序。
- 先写清 Coverage contract：`whole-article` 或 `local-complete`、来源边界、Central viewpoint、Reasoning spine 和排除内容。
- `whole-article` 能复述整篇的支配性观点及其关键理由；`local-complete` 明确对应哪个局部，并具备独立的问题、主张、理由和落点。
- 先有一句可成立的 Narrative promise；六格不是把文章随机切成六段。
- 六格分别承担起题、旧解/压力、转折、展开、限定/深化、收束，或另一条能覆盖完整 Reasoning spine 的叙事弧。
- 每格相较上一格都有可见变化；六格不应能任意互换顺序。
- 只看六格的 argument job 与短文案，读者仍能复述核心观点、至少一个关键理由，以及边界或含义。
- 至少有一个角色、物件、纸条、线或问题卡跨格连续出现，且状态会变化。
- 每格都有具体场景、动作和可见后果；禁止同一站姿配六句不同文案。
- 图内文案每格最多一条短句；若要求发布级中文准确度，交付无字/少字视觉底图和独立文案表。
- 不复刻用户参考图的角色、黄底、配色、文字或分镜；只吸收“六格叙事”的形式。
- 不为补齐叙事骨架发明原文没有的证据、反例、条件或边界；原文没有限定时用已有后果或含义深化。

### 模式门槛

- 故事、人物经历或生活文章至少保留两类事实锚点：地点、人物关系、具体动作、可见后果。
- 读者无需先解释隐喻，就能说出画面里发生了什么；否则判为过度抽象。
- 只有观点短句、方法论或概念说明，才允许以纯物件、线条和空白承担全部叙事。
- 先记录本张图使用的视觉模式：restrained-object-vignette / trace-object / character-led。
- restrained-object-vignette 不出现被迫拟人化的腿、眼睛、嘴、手、对白、姓名牌或说明性标签。
- restrained-object-vignette 的主体约占 20%-45%，留白约 55%-80%；一个物件、一个动作、一个后果足够成立。
- trace-object 只保留少量姿态或痕迹，文字最多 1-2 个短词，不滑回角色说明图。
- 只有 character-led 才检查烂笔头与破橡皮的完整身份、腿、眼睛和双角色互动规则。

### 基础检查（按模式执行）

- 比例符合 brief；如果使用 restrained-object-vignette，不为满足 16:9 而牺牲小主体与留白。
- 背景符合所选模式：物件小品可用纯白、暖白或极浅奶油色；character-led 默认干净白底。
- 画面只表达一个认知动作或核心结构。
- 动作归属清楚：物件小品看出物件正在做什么；character-led 才检查为什么是烂笔头、破橡皮或双角色同屏。
- character-led 双角色同屏时，两者必须各自承担不同动作，且互动本身表达文章锚点。
- character-led 单角色出场时，未出场角色必须通过痕迹在场，而不是被完全抹掉。
- 至少有生成或修正中的一个动作被明确看见。
- 画面中有痕迹与空白的关系：铅笔线、擦痕、灰屑、断芯、证据单或新空白。
- character-led 时，烂笔头残损可信：短、斜、脏黄、断芯风险、大包圈、残橡皮头。
- character-led 时，烂笔头眼睛一致：默认两个小黑点眼，紧张时也只能在点眼范围内变化，不能变成半睁线眼或卡通眼。
- character-led 时，破橡皮残损可信：粉色侧和灰白侧都破，不完整不干净，有裂缝、断面、灰痕。
- character-led 时，破橡皮正面形象一致：粉色半块在画面左侧、灰白半块在右侧，主要参差缺口在粉色半块外侧左边缘，上左角有塌损，中间是不规则近竖向裂缝，两条短腿清楚可见。
- character-led 时，破橡皮眼睛一致：只能是两条很短的黑色横线，压力状态也只能变成一高一低、断续、变短或一只眼闭上，不能变成点眼、眼白、瞳孔、眼眶或卡通眼。
- 中文标注符合所选模式：物件小品默认无文字，trace-object 最多 1-2 个短词，character-led 建议 3-6 个短词。
- 橙色只用于主路径或箭头。
- 红色只用于重点、问题、提醒、停止、裂缝或结果。
- 蓝色只用于证据、反馈或系统状态。
- 绿色只用于通过、保留、可用、被验证或继续走，且少用。
- 紫色只用于模型内部猜测、隐含状态或不确定中间态，且极少用。
- 蓝色局部标注优先贴近对象：近距离用短下划线或不加指针；远距离或方向必须明确时才用短蓝色手绘箭头。
- 颜色有明确语义，不是装饰；单张图通常只用 1-2 种批注色，最多 3 种。
- 没有复刻角色设定图姿势或上游小黑旧案例构图。

## 失败信号

出现以下情况，重生成或局部编辑：

- 左上角有“常见坑 / Workflow / 系统架构图 / 路线图”等标题。
- 画面像 PPT、课程课件、正式流程图。
- 六格只是在并列罗列 6 个概念，读者看不出开端、转折和落点。
- 用户没有指定模式，却未做自动路由就直接产出多张配图或六宫格。
- 为了优先展示六宫格而放宽五项门槛，导致内容需要密集小字、观点不完整或场景重复。
- 声称覆盖整篇文章，但实际只画了一个案例、一段方法或六句摘录。
- 声称是局部观点，却没有标明来源范围，或局部只有结论而没有论证闭环。
- 为了容纳整篇信息而把每格变成摘要卡，观点反而没有可读的推进。
- 六格角色、物件或场景没有连续线索，像六张随机小图。
- 每格只有不同标题，人物和动作完全不变。
- 为塞进正文而使用长段中文、多个对话泡或细小难读文案。
- 元素太多、箭头太多、节点太多。
- 文字变成大段解释。
- 背景有明显纸纹、阴影、渐变、噪点，或与所选模式不符（物件小品可用极浅奶油色，character-led 默认纯白）。
- 真实 UI 截图或科技感界面。
- 中文错字严重或标注不可读。
- 颜色被当成装饰色乱用，或单张图出现过多批注色。
- 蓝色标注旁出现漂浮角标、小 tick、半符号、封闭圈、完整框或含义不明的连接符号。
- 角色像儿童文具吉祥物。
- character-led 时，烂笔头像全新铅笔或没有大包圈和残橡皮头。
- character-led 时，烂笔头出现半睁线眼、大圆眼、眼白、睫毛或表情包眼。
- 破橡皮像完整干净的橡皮块，尤其粉色侧太完整。
- character-led 时，破橡皮缺口跑到灰白半块右端，或粉色/灰白左右关系反了，或两条短腿消失。
- character-led 时，破橡皮出现点眼、大圆眼、眼白、瞳孔、椭圆眼眶、完整眼皮形状、睫毛、笑眼或表情包眼。
- 双角色同屏时做同一种工作，缺少生成/修正张力。
- 双角色同屏只是因为它们是固定 IP，缺少必要互动。
- 单角色图里完全没有另一种力量的痕迹，导致它只是孤立角色图。
- 概念名词直接被写成画面标题，而不是转成可视动作。
- 没有可见后果：没有写痕、擦痕、空白、灰屑、断芯或证据。

## 迭代方法

- 太普通：把概念名词改成物理动作，让角色承担动作。
- 太复杂：删节点，只保留一个动作和 3-5 个短标注。
- 太可爱：强调 deadpan、damaged、lowly、not cute、not mascot。
- 太 PPT：去掉标题、边框、整齐网格和过多箭头，改成手绘场景。
- 出场关系不清：先写一句角色必要性判断。说不清互动必要性时，只保留承担核心动作的角色，并用铅笔线、擦痕、灰屑、空白、断芯或证据单补上另一种力量。
- 烂笔头太完整：加短身、掉漆、断芯、大包圈、残橡皮头。
- 破橡皮太完整：加粉色侧缺口、崩边、裂缝、灰痕、断面。
- 文字错：优先局部编辑；错得多就重生成并减少标注数量。

## 交付判断

高质量图应该让读者先看出当前动作和可见后果，然后 1 秒内看懂结构；character-led 还要看出角色分工，以及未出场一方留下的痕迹。

如果第一眼像教程页，而不是白纸上残损文具正在干笨活的认知草图，就不合格。
