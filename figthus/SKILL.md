# Figthus 正文配图

## 核心定位

Figthus 为中文文章自动选择并生成合适的视觉交付：多张正文配图、一张六宫格叙事连环画，或独立的克制物件小品。目标不是做商业插画、PPT 信息图、教程页或可爱文具海报，而是先理解文章里的认知锚点和完整观点单元，再选择最有内容价值的呈现方式。

Figthus 先在两种交付模式之间选择：

- article-illustration：一张或多张贴近正文段落的认知插图。
- narrative-comic-6：一张 3×2 的六宫格连环画，通过连续角色、场景和判断变化，把整篇或一个局部完整观点压成可独立传播的叙事。

确定交付后，再为单图或漫画各格选择三种视觉模式：

- restrained-object-vignette：默认。破橡皮先作为有磨损的物件出现，不强制腿、眼睛、对白或中文批注。
- trace-object：保留一点点姿态和痕迹感，但不回到完整角色。
- character-led：只有认知动作确实需要角色关系时，才使用一对残损文具：**烂笔头** 和 **破橡皮**。

不要因为文章是中文、需要“有趣”或需要保持 IP 就自动使用 character-led。

- 烂笔头负责先写、先错、先把混沌外化成痕迹。
- 破橡皮负责怀疑、擦改、校准、把假清楚擦出空白。

一句话：**不画知识点，画知识点里正在发生的那一下。**

## 工作流

### 0. 识别用户是否指定交付模式

- 用户明确要求“六宫格 / 连环画 / 分镜式总结 / 一张可独立传播的叙事图”：使用 `narrative-comic-6`。
- 用户明确要求多张、指定配图数量、指定插入段落、单张隐喻或正文 shot list：使用 `article-illustration`。
- 用户只说“为这篇文章配图 / 生成 Figthus 图 / 你判断怎么呈现”而没有指定形式：不要默认多张正文配图。先把交付模式标记为 `pending`，在消化正文后执行自动路由。

用户的明确选择优先。只有用户没有指定形式时才由 Skill 自主决定；不要为了展示新模式而推翻用户指定的数量、版式或用途。

只有 `narrative-comic-6` 允许一次生成单张多格合成图。它是交付模式，不替代每格所需的视觉规则；若使用 Figthus IP，通常以 character-led 为底层模式。

然后为标准单图或漫画的每格判断视觉模式：

先判断这张图是否真的需要角色：

先区分材料类型：故事、人物经历和生活文章必须保留地点、人物关系、具体动作、可见后果中的至少两项；不要把具体事件压缩成只有线、方块和空白的谜语。观点短句、方法论和概念说明才适合优先使用纯物件隐喻。

- 一个物件、一个小动作、一个后果就能成立：使用 restrained-object-vignette。
- 需要一点姿态或痕迹，但腿和脸不是必要信息：使用 trace-object。
- 去掉角色关系后，推进/阻止、生成/校准或写入/验收的张力会消失：使用 character-led。

默认优先级是 restrained-object-vignette → trace-object → character-led。把模式选择写进生成前的 brief，并在交付时说明。

### 1. 消化正文

先读用户给的正文、链接、Notion 页面、Markdown 文件或截图内容。提炼：

- 核心判断是什么
- 哪些段落承担认知转折
- 哪些内容适合视觉化
- 哪些地方只适合文字，不需要图
- 哪些地方有摩擦、代价、误区、断点、证据、修正或停止条件

如果交付模式是 `pending` 或 `narrative-comic-6`，还要把正文拆成候选“完整观点单元”：整篇的支配性主张，以及各局部中能独立形成“问题 → 主张 → 理由/证据 → 边界或含义 → 结论”的单元。

当交付模式是 `pending` 时，执行自动路由。只有下面五项全部通过，才选择 `narrative-comic-6`：

1. **观点完整**：存在一个可明确界定的 `whole-article` 或 `local-complete` 单元。
2. **确有推进**：可以形成至少一次张力、转折或理解变化；六格顺序不能任意互换。
3. **独立传播增益**：脱离正文后仍有清楚价值，一张连环画比零散插图更能保存核心判断及其理由。
4. **可视连续性**：能找到跨格持续线索，并设计至少三种不同的具体动作或可见后果。
5. **可压缩性**：在每格一句短文案的密度下仍能保住观点、关键理由和结论，不必把每格做成摘要卡。

五项全部通过时，优先选择 `narrative-comic-6`，再读取 `references/narrative-comic.md` 并选择 `whole-article` 或 `local-complete`。任一项不通过时选择 `article-illustration`；教程、参考资料、多个平行观点、需要分别贴近段落解释的长文，通常更适合该模式。只有一个认知动作时，使用一张普通插图或物件小品，不要硬扩成六格。

自动路由后先输出一条简短决策记录，然后按用户要求继续规划或直接生成：

```text
Delivery decision: {narrative-comic-6 | article-illustration}
Coverage candidate: {whole-article / local-complete 的范围；非漫画写不适用}
Why: {最关键的 1-2 个通过或失败原因}
Alternative rejected: {为什么另一种交付价值更低}
```

自动判断不等于停下来请求确认。用户已经明确要求生成时，输出决策记录后直接进入所选工作流；用户只要求分析或规划时才停在策略交付。

不要平均配图。优先选择“认知锚点”，例如：第一版被推出去、证据被拖回来、假清楚被擦掉、失败被分类、死循环被闸门拦住、好句子从废话里被擦出来、空白被重新开出来。

### 2. 把概念换成可视动作

不要直接画抽象名词，例如“AI Agent”“Loop Engineering”“反馈机制”“知识管理”。先把它们转成能被身体理解的动作：

```text
文章观点 -> 认知摩擦 -> 可视动作 -> 出场逻辑 -> 低科技隐喻 -> 插图
```

例如：

- “不是多试几次” -> 误区 -> 死循环被拦住 -> 破橡皮守停止闸。
- “结果要带证据回来” -> 证据回流 -> 蓝色证据单被拖回 -> 破橡皮拿证据，烂笔头准备改。
- “先有第一版才知道错在哪” -> 外化 -> 烂笔头推出第一条歪线。

默认先把破橡皮当成有磨损的物件，而不是吉祥物角色：用擦痕、灰屑、断线、接触面和新空白表达动作。只有当角色关系本身不可替代时，才进入 character-led；进入后再根据认知动作选择单角色或双角色。开始、外化、第一版可以只画烂笔头；擦改、校准、停止、裂开可以只画破橡皮。

出场角色必须先做“必要性判断”，不要在生成时临时凭感觉决定：

- 单角色：当核心动作只属于生成、外化、第一版、试错、擦改、校准、停止或压缩中的一方时，只让承担动作的角色出场，另一方只用痕迹在场。
- 双角色：只有当文章锚点本身包含两种不同力量的互动，且两者各自承担不可互换的动作时，才让双角色同屏。
- 双角色必须能一句话说明互动必要性，例如“破橡皮拖回证据，烂笔头据此改下一笔”“烂笔头向前冲，破橡皮守住停止闸”。如果说不清，就改成单角色。
- 不要为了 IP 完整、画面热闹或默认搭档关系而让两者同屏。

### 3. 先出配图策略或分镜脚本

如果交付模式是 `narrative-comic-6`，不要输出普通 shot list。按 `references/narrative-comic.md` 先输出：

- Coverage contract：覆盖整篇文章的核心观点，或一个边界明确、能独立闭合的局部观点
- 一句 Narrative promise
- 6 格 beat sheet：本格的 argument job、变化、场景、图内短文案、跨格持续线索、角色状态
- 选择它而不是多张正文配图的原因
- 明确未覆盖的支线、案例或次要观点
- 中文文案是否建议后期叠字

用户明确要求“生成 / 输出 / 做图”时，再生成单张 3×2 合成图，并将脚本保存为 `comic-script.md`；若只要求规划或分镜，则在 beat sheet 后停止。

如果用户只是说“分析怎么配图 / 思考哪些地方需要配图 / 先不要生图”，先给 shot list。每张图写清楚：

- 放在哪个段落后
- 图的主题
- 认知锚点
- 核心意思
- 结构类型
- 可视动作
- 视觉模式
- 出场角色或主物件
- 出场理由：角色模式才填写为什么是烂笔头、破橡皮或双角色同屏
- 未出场角色或未出场力量留下的痕迹
- 角色/物件状态：断芯 / 裂缝 / 擦痕 / 裂开了 / 胶带修补
- 建议元素
- 建议中文标注词

默认 4-8 张。文章很短时 1-3 张；长文也不要轻易超过 9 张。够用就好，避免把正文做成画册。

### 4. 生成

当用户明确要求“生成 / 输出 / 做图”时，`narrative-comic-6` 的生成例外是：根据 `references/narrative-comic.md`，一次生成一张完整 3×2 六宫格合成图；不要拆成六张普通图，也不要把已生成的普通图拼贴成网格。优先完成分镜和视觉连续性，发布级长文案建议后期叠字。

标准文章配图仍按以下规则单张生成：

如果用户明确要求“生成 / 输出 / 做图 / 帮我生成”，不要停下来等确认；用内置 `image_gen` 每张单独生成。不要把多张图拼在一张里。

每张图只讲一个核心结构或认知动作。提示词必须包含当前视觉模式的最低约束：

- brief 指定的比例；默认仍可用 16:9，但不要为了版式强行做成说明图。
- restrained-object-vignette：暖白或浅奶油底色，主体约占 20%-45%，留白约 55%-80%，通常不加文字、箭头、节点、边框或标题。
- trace-object：保留一个轻微倾斜、接触、擦痕或短动作线，文字最多 1-2 个短词。
- character-led：只有在角色关系必要时，才使用现有烂笔头与破橡皮的身份、动作和眼睛规则。
- 深石墨色手绘线稿，线宽有自然变化；避免均匀矢量描边和封闭轮廓。
- 低饱和灰粉、灰白、木色或单一蓝/赭色点缀；颜色服务于动作，不做装饰。
- 当前模式下的核心动作、可见后果，以及没有出场的力量留下的痕迹。
- 禁止 PPT、商业插画、儿童文具海报、复杂架构、固定小黑角色、左上角类型标题。

不要复刻过往案例。角色设定图只用于校准形象，不要复用它的分镜、姿势或标注作为最终正文插图。

### 5. 检查与迭代

生成后检查 `references/qa-checklist.md`；`narrative-comic-6` 还要检查 `references/narrative-comic.md` 的读序和分镜要求。如果出现以下问题，优先重生成或局部编辑：

- 角色像儿童文具吉祥物
- 烂笔头太完整、太新、没有大包圈和残橡皮头
- 破橡皮太完整、太干净、粉色侧没有残损
- 出场角色与痕迹关系不清
- 画面没有痕迹与空白的关系
- 画面太满
- 太像流程图/PPT/课程页
- 中文太多或错字严重
- 左上角出现“常见坑/流程图/系统架构图/路线图”等标题
- 背景不符合所选模式：物件小品出现明显纸纹、渐变或阴影；character-led 偏离干净白底

### 6. 保存交付

如果用户在 workspace 内工作，把最终图复制到：

```text
assets/<article-slug>-figthus/
```

按顺序命名：

```text
01-topic-name.png
02-topic-name.png
```

保留原始生成文件，不要覆盖已有资产，除非用户明确要求替换。

`narrative-comic-6` 额外保存 `comic-script.md`，并将合成图命名为 `01-narrative-comic-6.png`。

## 输出口径

生成前的策略输出要短而准。生成后的交付要包含：

- 生成了几张
- 每张图的用途
- 使用的视觉模式
- 自动或显式选择的交付模式，以及简短 Delivery decision；若为 narrative-comic-6，再附上覆盖范围、排除内容、叙事承诺和 6 格职责
- 保存路径
- 哪些图最稳，哪些图是可选

不要长篇解释风格理论；让图自己说话。
